# 《断层战线》资产验证切片

## 目标

在继续扩展玩法前，先证明“正式 3D 母资产 → 固定等距渲染 → 2.5D 运行时精灵”能够明显超过当前程序几何模型。首个验证对象为玩家中型坦克 `FF-MBT-01`。

## 当前事实

- 已完成原创多视图概念基准：`assets/concepts/ff-mbt-01-turnaround-v1.png`。
- 概念图只提供可见外观，不包含隐藏几何，不能宣称已经生成 3D 模型。
- 已在 E 盘项目工具目录部署 Blender 4.5.12 LTS 便携版；Microsoft Store 5.2 版因 WindowsApps 权限不能用于后台自动化，本流程未依赖它。
- `tools/blender/build_ff_mbt_01.py` 已生成可编辑母资产、GLB、1024² 预览、8个 192² 透明方向帧和伴随 JSON。
- 玩家堡垒坦克已在 `scene.ts` 中异步加载该 GLB，保留 `chassis_root / turret_yaw / barrel_pitch / muzzle_socket` 语义节点；失败时回退旧程序模型。
- 真实游戏默认镜头已确认模型加载、接地、选择环、车体朝向和独立炮塔节点正常，页面无加载错误。

## FF-MBT-01 母资产契约

### 模型

- 格式：GLB 2.0，米制，导出后 Y 轴向上、前方为 +Z。
- 尺寸目标：长 5.2m、宽 3.2m、车体顶高 1.6m、炮塔顶高不超过 2.6m。
- 枢轴：车体根节点位于履带接地面的几何中心；模型必须在 Y=0 接地。
- 建议预算：15k–25k 三角形，最多 3 个材质槽，单套 1024² BaseColor/Normal/ORM。
- 小零件必须服务于 96px 战略缩放下的轮廓；禁止只在资产查看器中可见的无效细节。

### 语义节点

```text
FF_MBT_01
├─ chassis_root
│  ├─ track_left
│  ├─ track_right
│  ├─ exhaust_left
│  └─ exhaust_right
├─ turret_yaw
│  ├─ barrel_pitch
│  │  └─ muzzle_socket
│  └─ commander_hatch
└─ selection_anchor
```

- `turret_yaw` 必须能绕本地 Y 轴独立旋转。
- `barrel_pitch` 和 `muzzle_socket` 必须保持稳定命名，供弹道与枪口特效定位。
- 碰撞继续使用模拟中的简化圆形半径，不从可见网格自动推导。

## 2.5D 渲染契约

- 正交镜头：45° 方位角、55° 仰角，与当前战略镜头一致。
- 方向：车体 8 方向，每 45° 一帧；炮塔单独渲染 16 方向，每 22.5° 一帧。
- 输出：透明 WebP 或 PNG 图集，单帧 192×192，四周至少 12px 安全区。
- 分层：车体、炮塔、接触阴影分开输出，使运行时仍能独立瞄准并控制阴影透明度。
- 锚点：每帧共享同一接地点；炮塔层共享同一旋转中心；枪口位置写入伴随 JSON。
- 色彩：sRGB；透明边缘不得出现黑边或背景色溢出。

## 运行时接口

```ts
interface DirectionalSpriteAsset {
  id: string;
  bodyAtlasUrl: string;
  turretAtlasUrl?: string;
  shadowAtlasUrl?: string;
  bodyDirections: 8;
  turretDirections?: 16;
  frameSize: { width: 192; height: 192 };
  pivot: { x: number; y: number };
  turretPivot?: { x: number; y: number };
  muzzleByDirection?: Array<{ x: number; y: number }>;
}
```

模拟层仍只保存世界位置、车体朝向、炮塔朝向、半径和权威战斗状态；精灵方向选择完全属于表现层，不进入回放哈希。

## 通过标准

- 在真实游戏默认缩放中，坦克以约 72–110px 高度显示时仍能辨认车头、炮塔、履带和阵营色。
- 八方向不存在轮数、炮管长度、舱盖或装甲结构跳变。
- 炮塔旋转不带动车体，枪口特效位置不漂移。
- 地面接触稳定，没有漂浮、脚底切边或方向帧抖动。
- 一屏 40 辆坦克仍保持稳定帧率，纹理不重复上传，精灵使用共享图集。
- 与当前程序几何坦克做同镜头 A/B 截图，只有当新资产在轮廓、材质和世界一致性上明显胜出，才扩展到采矿车与建筑。

## 首轮验证结论

- 技术链路：`pass`。Blender 后台建模、GLB 导出、透明方向帧、Three.js 异步加载、节点拾取与玩法回退均已打通。
- 轮廓与接地：`pass`。真实战略镜头下坦克明显区别于旧程序模型，履带、六轮、炮塔和炮管可辨认。
- 材质技术链：`pass`。已生成并导出 6 组 256² BaseColor/Normal/ORM 验证纹理，喷漆装甲采用低金属度，裸露钢件保留金属响应；浏览器实战光照下不再因缺少环境反射而发黑。当前纹理仍是程序化验证品质，正式英雄资产还需要人工绘制的边缘磨损、污渍流向、编号与阵营徽记。
- 2.5D 分层：`pass`。同一 `.blend` 已稳定导出车体 8 方向、炮塔 16 方向、独立接触阴影和 JSON 元数据；`ff_mbt_01_directions_preview.png` 证明三个图层可按共享锚点合成。当前游戏继续直接显示 GLB，图集打包与运行时精灵切换属于后续性能路线。
- 实机复核：`pass`。更新后的 2.47MB GLB 已在真实游戏默认镜头中完成选择、聚焦、缩放与炮塔节点检查，浏览器错误/警告日志为空。
