# 动态表现验收

## 范围

本轮把正式 Blender 母资产从“静态模型”推进为由真实玩法状态驱动的战场表现层。动画不依赖预录角色动作，也不改变模拟、寻路、碰撞或回放数据。

- 载具：根据相邻渲染帧的真实世界位移计算轮组转动、低幅车体起伏与转向侧倾。
- 步兵：读取三人小队语义节点，以错相节奏表现步行，避免整组同步漂移。
- 采集：双方采矿车保留三个独立货舱槽，按权威 `cargo / cargoCapacity` 显示空载、低载、半载和满载；采集滚筒只在真实 gather 状态旋转。
- 生产：工厂门、兵营门和吊机不再读取简单的队列布尔值，而是观察首项 `remaining` 是否真实下降；停产时机构停机，接近出厂时门体进一步开启。
- 施工：未完工建筑始终保留静态脚手架，但进度扫描只在 `buildProgress` 真实增长时运动；完工后自动移除。
- 受损：建筑在生命值阈值以下持续显示烟雾和余烬，沿用统一特效预算。
- 降动态：系统偏好或 `dynamic-review-reduced` 夹具会关闭摇摆、轮转、粒子与脉冲，但保留施工、生产和受损的静态状态识别。

## 可复现夹具

- `/?fixture=dynamic-review&quality=high`：3 个真实移动单位、1 辆半载采矿车、2 座持续排队的真实生产建筑、1 座施工建筑、1 座重损建筑。
- `/?fixture=dynamic-review-reduced&quality=high`：同一权威场景的静态替代版本。

## 浏览器证据

- 桌面 1280×720 高画质：完整资产稳定后约 401 calls / 88,566 triangles / 42 textures；诊断字段确认 2 个货舱槽、1 个采集滚筒、1 个吊机、1 扇工厂门、1 扇兵营门和 1 个真实施工扫描处于工作状态。
- 手机 390×844 低画质降动态：约 216 calls / 54,830 triangles / 41 textures；`presentationReducedMotion=true`，粒子和连续摆动关闭，但货舱、开门、施工和受损静态状态仍可读。
- 完整突破场景 1280×720 冷/热启动均为 42/42 资产、0 失败、0 重试、100 张已上传纹理，稳定约 118k 三角形；390×844 低画质约 52k 三角形 / 57 纹理，浏览器日志无 warning/error。

## 结论

该实现将 Blender 可见网格、模型语义节点、权威玩法状态和轻量运行时动画连成统一管线。采矿车货舱、采集滚筒、工厂门、兵营门和吊机均通过资产契约验证“语义节点下确有可见子网格”，不再出现只移动空节点的假动画。
