# 《断层战线》v0.6.0 当前交接

更新时间：2026-08-10

## 1. 当前结论

项目已经完成“桌面 Web 单地图 RTS 高完成度垂直切片”目标：玩家可以从任务简报选择难度，完成采集、建造、生产、科技和战斗；正确路线目标为约 8–12 分钟自然胜利，严重弃守会在难度对应窗口自然失败；同时支持保存、载入、跨页面继续战况和重新部署。

它不是完整商业 RTS。多地图、完整双势力、正式战役、多人联机、正式音乐/配音和长期进度不在当前交付范围。

详细复盘与架构以[项目复盘与技术总览](project-retrospective-and-architecture.md)为准，全部文档入口见[文档索引](index.md)。

## 2. 运行与入口

```powershell
npm.cmd install
npm.cmd run dev
```

规范本地地址：<http://127.0.0.1:4180/>

主要入口：

- `/`：00:00 暂停的任务简报；三档难度；存在有效突破战存档时可继续上次战况。
- `/?fixture=breakthrough-demo`：标准黄金对局。
- `/?fixture=breakthrough-demo-cadet`：新兵难度。
- `/?fixture=breakthrough-demo-veteran`：老兵难度。
- `/?fixture=default`：自由经营沙盒。

更多评审夹具见根目录 [README](../README.md)。

## 5. 技术边界

- 当前 UI 是原生 DOM/CSS，不是 React。
- 当前模拟在主线程以 20Hz 固定步进运行，不在 Web Worker。
- 当前存档是 `localStorage` 单槽命令日志，不是 IndexedDB 多槽快照。
- 当前战场直接渲染 GLB；方向帧管线曾完成验证，但没有替换正式运行时。
- 当前已有 GitHub Pages 静态公网演示，但无后端、账号或联机服务。
- 源码现已纳入 [GitHub 仓库](https://github.com/yydshly/0810-faultline-front)并建立版本标签；2026-08-09 的既有发布 ZIP 早于仓库初始化，所以其 manifest 提交身份仍为空，不能冒充提交绑定制品。

这些差异已在[项目复盘与技术总览](project-retrospective-and-architecture.md)中记录，避免把早期设计愿景误报为已实现功能。

## 6. 建议接续顺序

1. 冻结新资产与新系统，保留当前 ZIP 为基线。
2. 在干净浏览器和普通桌面电脑上对最终 ZIP 做三档冷启动烟测。
3. 邀请 3–5 名陌生玩家完成封闭 Alpha，只记录并修复阻断理解或完成对局的问题。
4. 增加正式战役独立存档、3 个手动槽和自动存档。
5. 将关键浏览器路径固化为端到端自动回归。
6. 建立 CI，在明确提交上自动执行 TypeScript、Vitest、生产构建和 42 项资产合同检查，并生成提交绑定制品。
7. Alpha 通过后，只选择“公开演示版”或“第二地图/第二势力”中的一条继续。

## 7. 当前不建议

- 继续无目标地重制已经通过战略镜头验收的模型。
- 在没有低配帧时间证据时重写渲染器或迁移引擎。
- 同时开启移动端、多人联机、多地图、第二势力和完整战役。
- 使用旧 `prototype-coverage` 或旧快速突击文档中的测试数和对局时长代表当前版本。
